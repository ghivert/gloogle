Le monorepoThe monorepo

Deux applications, quatre paquets. galaxy est la charnière : c'est le seul code que le backend et le frontend partagent — les types de données avec leurs encodeurs/décodeurs JSON, et depuis b63a44c l'IR de signatures elle-même.

Two applications, four packages. galaxy is the hinge: it is the only code the backend and the frontend share — the data types with their JSON encoders and decoders, and since b63a44c the signature IR itself.

apps/jupiter backend

Serveur Wisp/Mist sur Erlang, pool Postgres via pog, workers périodiques sous supervision OTP. Contient l'ingestion Hex, toutes les requêtes SQL, et le front-end Gleam data/ir/from_gleam — seul morceau à dépendre de gleam_package_interface, et c'est précisément pour ça qu'il ne suit pas l'IR dans galaxy.

A Wisp/Mist server on Erlang, a Postgres pool through pog, periodic workers under OTP supervision. Holds Hex ingestion, every SQL query, and the Gleam front-end data/ir/from_gleam — the only piece depending on gleam_package_interface, which is exactly why it did not follow the IR into galaxy.

apps/venus frontend

SPA Lustre (MVU). Consomme l'API JSON de jupiter et rend les signatures. Dépend encore de gleam/package_interface pour l'affichage — c'est ce que le refactor IR vise à supprimer.

A Lustre SPA (MVU). Consumes jupiter's JSON API and renders signatures. Still depends on gleam/package_interface for display — which is exactly what the IR refactor aims to drop.

Le pipeline d'ingestionThe ingestion pipeline

Toutes les 10 secondes, tasks/hex pagine l'API Hex à partir du dernier horodatage vu (table hex_read), et ne garde que les paquets plus récents. Chaque release fraîche est téléchargée, son package_interface structuré est lu, puis chaque déclaration traverse la chaîne ci-dessous.

Every 10 seconds, tasks/hex pages through the Hex API starting from the last timestamp it saw (the hex_read table), keeping only newer packages. Each fresh release is downloaded, its structured package_interface is read, and then every declaration travels the chain below.

→
02 api/hex_repo Récupération du tarball de la release, extraction (plasma/tar). Fetches the release tarball and extracts it (plasma/tar).
→
03 api/signatures Parcours des modules : types, alias, constantes, fonctions. Walks the modules: types, aliases, constants, functions.

→

Les trois sorties de l'étape 6 viennent d'un seul appel, dans api/signatures.structured — c'est le point où l'invariant « une seule représentation stockée » est tenu :

All three outputs of step 6 come from a single call, in api/signatures.structured — this is where the "one stored representation" invariant is actually held:

/// Alpha-rename a lowered declaration, then derive the columns that hang off the
/// IR: the encoded `signature_ir` and its phase-1 fingerprint (`arity`,
/// `type_names`). All three come from the one canonical declaration.
fn structured(declaration: ir.Declaration) -> #(json.Json, Int, List(String)) {
  let declaration = ir.alpha_rename_declaration(declaration)
  let #(arity, type_names) = ir.fingerprint(declaration)
  #(ir.encode(declaration), arity, type_names)
}

Les types récursifs sont insérés deux fois. Avant de calculer sa signature, upsert_type_definitions écrit une ligne placeholder (signature vide, signature_ir à null, arity: 0, type_names: []) pour que le type existe déjà quand il se référence lui-même. Le second upsert, sur le conflit (package_module_id, name), remplit les vraies valeurs.

Recursive types are inserted twice. Before computing its signature, upsert_type_definitions writes a placeholder row (empty signature, signature_ir as null, arity: 0, type_names: []) so the type already exists by the time it refers to itself. The second upsert, on the (package_module_id, name) conflict, fills in the real values.

Le cache d'archives (étape 02) a trois étages, et une stack locale. api/hex_repo cherche le tarball d'une release d'abord sur le disque, puis dans le bucket S3, et seulement ensuite sur repo.hex.pm — chaque niveau remplit le précédent. Le client aws/s3 lit la forme du bucket dans BUCKET_URI : un hôte nu (hex-mirror.s3.fr-par.scw.cloud, la prod sur Scaleway) donne https et des objets en /<clé> ; une URL complète (http://localhost:29000/gloogle) donne le schéma et le port écrits et des objets en /<bucket>/<clé> (path-style). C'est ce qui permet la stack locale infra/local/compose.yml — Postgres sur 25432, RustFS sur 29000/29001, ports choisis loin de tout — alimentée depuis la prod par infra/local/scripts/seed-local.sh : miroir du bucket Scaleway (8 083 archives, 576 Mio) et restauration de la base depuis l'instantané de prod apps/jupiter/db/gloogle_migrated.sql.gz (2 juillet 2026, hors git ; la prod vit chez Render, pas chez Scaleway), suivie de dbmate up pour les migrations plus récentes. Ce qui ne se régénère pas et justifie la copie : hex_read, analytics, analytics_timeseries, search_analytics, l'historique de popularité.

Les colonnes dérivées de l'IR se re-dérivent sans Hex : tasks/backfill_ir. Chaque release garde son package_interface brut en base. La tâche ponctuelle (gleam run -m tasks/backfill_ir, hors superviseur) parcourt les releases par keyset sur package_release.id, décode l'interface, abaisse chaque déclaration par data/ir/from_gleam, passe par api/signatures.structured — le seul endroit où signature_ir, arity et type_names naissent de la déclaration canonique, pour l'ingestion comme pour le backfill — et met à jour la ligne (package_module_id, name, kind), une transaction par release, sans toucher aux autres colonnes. Idempotente ; c'est elle qui a rempli l'instantané local (502 188 des 502 237 lignes, en 3 min 26 ; les 49 restantes appartenaient à deux releases dont l'interface stockée ne décrivait pas tous les modules ingérés — supprimées de la base locale, le sync Hex les réingère puisque leurs paquets ont bougé après le curseur) dont les colonnes IR étaient vides. Deux pièges : la lancer avec les binaires réels (les shims mise réinjectent le DATABASE_URL du développeur), et lire hors transaction tout ce qui se décode par nom de colonne (la connexion transactionnelle de pog rend des tuples).

Une release se réextrait depuis la base : tasks/reextract. A release re-extracts from the database: tasks/reextract. The IR-derived columns re-derive without Hex: tasks/backfill_ir. Every release keeps its raw package_interface in the database. L'IR de signaturesThe signature IR

Le cœur du refactor. Un nœud n'existe que s'il ajoute un pouvoir d'expression irréductible — tout ce qui est du sucre sur une combinaison de nœuds existants est une règle d'abaissement du front-end, pas un nœud. Défini dans packages/galaxy/src/data/ir.gleam : l'IR vit désormais dans galaxy, donc venus pourra la rendre. Le front-end Gleam data/ir/from_gleam, lui, reste dans jupiter.

The heart of the refactor. A node exists only if it adds irreducible expressive power — anything that is merely sugar over a combination of existing nodes is a front-end lowering rule, not a node. Defined in packages/galaxy/src/data/ir.gleam: the IR now lives in galaxy, so venus will be able to render it. The Gleam front-end data/ir/from_gleam, however, stays in jupiter.

Les deux invariantsThe two invariants

Ils expliquent presque tout le reste du design :

They explain almost everything else in the design:

1 · Les variables portent index et nom

1 · Variables carry an index and a name

(a) -> b et (x) -> y partagent les mêmes indices, donc l'unificateur lit index directement. L'alpha-renommage est précalculé à l'ingestion, jamais à la requête. Le name survit pour l'affichage — en Gleam c'est la lettre dérivée de l'id (0 → a), en TS/Java le vrai <T, E>.

(a) -> b and (x) -> y share the same indices, so the unifier reads index directly. The alpha-rename is precomputed at ingestion, never at query time. The name survives for display — in Gleam it is the letter derived from the id (0 → a), in TS/Java the real <T, E>.

2 · Une méthode est une fonction receveur-en-premier

2 · A method is a receiver-first function

Ce qui la fait converger avec l'idiome pipe-first de Gleam (foo |> bar(x)), où le receveur est déjà le premier argument. Le flag is_method n'est gardé que pour pouvoir booster ou filtrer.

Which makes it converge with Gleam's pipe-first idiom (foo |> bar(x)), where the receiver is already the first argument. The is_method flag is kept only so same-shape methods can be boosted or filtered.

La notation canoniqueThe canonical notation

Un seul parseur, un seul printer (ir.to_string). C'est à la fois la syntaxe de requête et la chaîne canonique relisible. Non ambiguë par construction : les variables sont $n, donc aucune devinette lexicale variable-vs-nominal. Gleam et TypeScript se rejoignent exactement :

One parser, one printer (ir.to_string). It is both the query syntax and the re-readable canonical string. Unambiguous by construction: variables are $n, so there is no lexical variable-vs-nominal guessing. Gleam and TypeScript land on exactly the same form:

// Gleam
fn(Result(a, b), fn(a) -> c) -> Result(c, b)

// TypeScript
function map<A, B, C>(r: Result<A, B>, f: (a: A) => C): Result<C, B>

// ── les deux front-ends produisent la même forme canonique ──
( Result<$0, $1>, ($0) -> $2 ) -> Result<$2, $1>
// Gleam
fn(Result(a, b), fn(a) -> c) -> Result(c, b)

// TypeScript
function map<A, B, C>(r: Result<A, B>, f: (a: A) => C): Result<C, B>

// ── both front-ends produce the same canonical form ──
( Result<$0, $1>, ($0) -> $2 ) -> Result<$2, $1>

Il n'y a pas de ? dans la notation, et pas de nœud Optional : la nullabilité est résolue par le front-end avant d'atteindre la forme canonique. Promise non plus n'est pas un nœud — c'est un Named ordinaire dans tous les langages, donc chercher -> Promise<B> marche gratuitement.

There is no ? in the notation, and no Optional node: nullability is resolved by the front-end before it reaches the canonical form. Promise is not a node either — it is an ordinary Named in every language, so searching -> Promise<B> works for free.

Les types importantsThe types that matter

Ces types ne sont pas des pairs : ils se succèdent. Une déclaration entre par pi.Type, devient une ir.Declaration, se pose en jsonb, ressort en TypeSearch, et finit rendue. D'où la forme choisie ici : un exemple réel suivi de bout en bout, puis une fiche par type — définition, stockage, usage. Les types qui sont réellement des pairs restent en tableau, plus bas.

These types are not peers: they follow one another. A declaration enters as a pi.Type, becomes an ir.Declaration, settles as jsonb, comes back out as a TypeSearch, and ends up rendered. Hence the shape used here: one real example traced end to end, then one card per type — definition, storage, usage. The types that genuinely are peers stay in a table, further down.

4 ir.Declaration ← from_gleam (jupiter)

The lowering. Var keeps the pi id as its index, and the letter as its name — the same rule as rendering, so the two agree. Result is a prelude type, so its module is emptied.

5 alpha_rename_declaration ← ir

Les indices repassent en ordre de première apparition (paramètres, puis retour). Ici les ids du compilateur étaient déjà 0, 1, 2 dans cet ordre, donc rien ne bouge — mais c'est cette passe qui rend (a) -> b et (x) -> y identiques. Elle tourne une fois, à l'ingestion, jamais à la requête.

Indices are renumbered in first-appearance order (parameters, then return). Here the compiler ids already were 0, 1, 2 in that order, so nothing moves — but this is the pass that makes (a) -> b and (x) -> y identical. It runs once, at ingestion, never at query time.

The jsonb column. Self-describing: every node carries its kind, so ir.decoder() reads it back with no context.

8 La forme canoniqueThe canonical form ← ir.to_string

Non stockée — régénérable à tout moment depuis signature_ir. C'est cette forme que la requête d'un utilisateur devra rejoindre, et celle sur laquelle Gleam et TypeScript convergent.

Not stored — regenerable at any time from signature_ir. This is the form a user's query will have to meet, and the one Gleam and TypeScript converge on.

(over: Result<$0, $1>, with: ($0) -> $2) -> Result<$2, $1>

Ce que l'exemple apprend et qu'un tableau tait : le nom des variables de type est perdu dès le package_interface. Ce que la page appelle « le nom source gardé pour l'affichage » n'est, en Gleam, qu'une lettre recalculée depuis un id — e devient b. La distinction ne prendra son sens qu'avec TS ou Java, où <T, E> existe vraiment.

What the example teaches and a table cannot: type-variable names are lost as early as the package_interface. What the design calls "the source name kept for display" is, in Gleam, merely a letter recomputed from an id — e becomes b. The distinction only earns its keep with TS or Java, where <T, E> genuinely exists.

La cascade de rechercheThe search cascade

Une requête traverse six tiers, du plus précis au plus large. Chaque tier reçoit la concaténation de tous les résultats précédents et s'en défausse (exec_search filtre par list.contains), si bien qu'un même item n'apparaît qu'une fois, dans son tier le plus précis. Chaque requête SQL est plafonnée à 100 lignes et triée par package_rank DESC, ordering DESC, où ordering est package_release.version_ordering, la version découpée en int[] par Postgres. Une requête structurellement typée s'arrête au premier tier : si elle parse en fonction, tuple ou type paramétré (fn(List(a)) -> Bool, List(Int), #(a, b)), les cinq tiers texte ne tournent pas — ils ne feraient que moudre du trigram et du tsvector sur une chaîne en forme de code, pour des secondes et des timeouts, et rendre du bruit — et la réponse porte "narrowed": true. ?broad=true les relance tous : c'est le bouton « Widen the search » que venus affiche sous les résultats de type quand la réponse est narrowed (UserRequestedBroadSearch → api.get_search(broad: True) ; la réponse élargie remplace celle en cache et le bandeau disparaît). Un simple identifiant (Connection, is_empty) n'est pas structurel et traverse toujours les six tiers (handlers.structural). Second garde-fou, sur les trois tiers de contenu (trigrammes et les deux tsvector) : ils ne tournent que si la requête porte un mot d'au moins trois caractères (handlers.searchable) — en dessous, pg_trgm n'extrait aucun trigramme d'un motif LIKE '%io%' et le GIN rend toute la table, et le tsvector anglais de fn(a) -> a se réduit au jeton fn, présent dans 377 k lignes (750 ms de bruit sur le snapshot local).

A query travels through six tiers, from the most precise to the broadest. Each tier receives the concatenation of every previous result and discards those (exec_search filters with list.contains), so a given item appears exactly once, in its most precise tier. Every SQL query is capped at 100 rows and ordered by package_rank DESC, ordering DESC, where ordering is package_release.version_ordering, the version split into an int[] by Postgres. A structurally typed query stops at the first tier: if it parses as a function, a tuple or a parameterised type (fn(List(a)) -> Bool, List(Int), #(a, b)), the five text tiers do not run — they would only grind trigram and tsvector searches over a code-shaped string, for seconds and timeouts, and return noise — and the response carries "narrowed": true. ?broad=true runs them all again: the "Widen the search" button venus shows under the type results when the response is narrowed (UserRequestedBroadSearch → api.get_search(broad: True); the widened response replaces the cached one and the banner goes away). The verdict is not a boolean but a Match carrying a cost — the Hoogle lesson: matching returns a cost, and the cost is the ranking. Two constructors = two result buckets, cost orders within:

1 · Equivalent(cost) — alpha-équivalence. Un Var de requête ne matche qu'un Var candidat, sous une liaison injective dans les deux sens : ($0, $1) -> $0 matche fn(a, b) -> a à coût 0, fn(a, b) -> b modulo réordonnancement (surtaxé), et fn(a, a) -> a pas du tout — ça, c'est de la subsomption. 1 · Equivalent(cost) — alpha-equivalence. A query Var matches a candidate Var and nothing else, under a mapping injective both ways: ($0, $1) -> $0 matches fn(a, b) -> a at cost 0, fn(a, b) -> b modulo reordering (surcharged), and fn(a, a) -> a not at all — that is subsumption. The cost counts what the _s absorb (1 per concrete node): the genuinely polymorphic candidate surfaces first.

2 · Subsumed(cost) — subsomption directionnelle : l'un des deux est plus général que l'autre. ($0) -> $0 trouve aussi Int -> Int (requête plus générale) et (List<Int>) -> Bool trouve fn(List(a)) -> Bool (candidat plus général). 2 · Subsumed(cost) — directional subsumption: one side is more general than the other. La référence croisée résolue (ref)

The resolved cross-reference (ref)

Pas stockée non plus, et pour une raison de fond : une ref résout une plage semver contre un ensemble de versions qui évolue. Elle doit donc se calculer au moment de la requête, en respectant l'exigence de la release appelante — via une future table package_dependency. Not stored either, and for a fundamental reason: a ref resolves a semver range against an evolving set of versions. So it must be computed at query time, respecting the using release's requirement — via a future package_dependency table. It is precisely so that this resolution is a join rather than stored state that Name carries package and module.
